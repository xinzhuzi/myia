# PRD — 仪表盘趋势卡「今日」档退化修复(单点图 + 两端同日期)

- **优先级**:P2(UX 呈现缺陷,仪表盘第一屏观感;无数据丢失、无功能不可用)
- **报障**:主人 2026-10-07 截图报「UI布局有问题」(证据见 `evidence/` 两张)
- **方向决议**(主人已批「立档」,方向按主会话推荐 A,备选 B 不做):
  - **A(本档范围)**:两图(采集量趋势/成功率)图窗设 **7 天下限**,与概览窗解耦;概览四格与口径文案不随图变宽
  - B(非目标):「今日」档换形态(当日分轮柱状/大数字卡)
  - **grill 六问全批按推荐**(2026-10-07,决议并入 R/AC 与 design D2/D5/D6/D8):下限 7 / 标签如实不加解释文案 / 成功率摘要跟图窗 / 全零刻度守卫纳入 / 同窗切换不弃旧窗 / 像素验收走 devUrl

## 1. 背景与根因(证据矩阵,全部亲核)

主人截图的仪表盘第一屏:「采集量趋势」全宽 hero 卡大面积空白,仅图心一个 ~12px 孤点;x 轴两端**同一个日期**「2026-10-06」,中间悬「峰值 134 条/日」;y 轴刻度 134/67/0。像素扫描实证:趋势图区域唯一彩色墨迹为 x∈[712,723]、y∈[885,896] 单点;卡片边框对齐无错位(下半屏实测 494/1104/1130/1740,两列 610px/间距 26px,两行完全对齐——**卡片错位不存在,不在本档范围**)。

机制链(每环代码亲核):

| 环节 | 位置 | 事实 |
|---|---|---|
| 概览窗默认「今日」 | `desktop/ui-src/src/screens/dashboard/api.ts:439` | `OVERVIEW_WINDOW_DEFAULT = "today"`,人人打开仪表盘即此档 |
| 今日 → 1 天趋势窗 | `api.ts:444` `overviewTrendDays` | 概览窗直接换算成 store.trend 的 days 参数 |

| 成功率线同窗耦合 | `dashboard-screen.tsx:801,817` | `fetchOutcomeWindow(days)` 与 `refreshTrend(overviewTrendDays(...))` 同一 days,今日档同样退化成单点 |

## 2. 需求

- **R1 图窗下限**:概览窗=「今日」档时,采集量趋势与成功率两图渲染「近 7 天」补零窗口(UTC 逐日,口径与现状一致);不再出现单点图与两端同日期轴行;全零窗(7 日皆 0)不出现重复的「0/0/0」y 轴刻度。
- **R2 口径解耦不撒谎(两分法,design 阶段修案)**:概览四格与 verdict 状态句的窗口语义**仍是概览窗**(今日档=今日 UTC 当日,数字与修复前一致);趋势卡内两图及其卡脚合计、峰值、aria、成功率摘要**跟图窗**(今日档=近 7 天)并如实标注。禁止任何「数字与所标窗口不符」——今日档采集格显示 7 天和、或 7 天图挂着「今日」标签,都算违例。(初稿曾把卡脚归概览窗,与 AC3「图注记跟图窗」自相矛盾,已修。)
- **R3 零回归**:7/14/30 天档全屏行为与现状完全一致(数据、标签、aria)。
- **R4 修装配不改组件语义**:sparkline 单点渲染语义本身不动(其他消费面在);修复在窗口装配/切片层完成。

## 3. 验收标准

- **AC1** 默认进仪表盘(今日档):两图各 ≥2 个数据点且有折线;趋势轴行首末日为不同日期;「峰值 N 条/日」注记位置语义不变;全零态=平线、无重复 y 刻度、卡脚如实「共 0 条 · 峰值 0 条/日」。
- **AC2** 今日档下概览四格与 verdict 状态句数字与修复前逐格一致(采集格=今日当日数:7 天 trend 输入经概览窗切片仍得当日行);成功率区「累计成功率」摘要与图同窗(今日档=近 7 天,如实标注——修案:初稿曾写「仍今日」,按 R2 两分法裁定跟图窗,数字-标签同窗)。
- **AC3** 卡面口径注记与实际图窗一致:今日档两图标「近 7 天」(或等义人话);7/14/30 档沿用 `windowLabel` 现文案。
- **AC4** 单测:今日档 trend/outcome 图窗=7(或引入的图窗下限常量);7/14/30 档传参不变;轴行无重复日期断言;四格今日口径切片回归断言(7 天 trend 输入 → 采集格=当日行);全零窗 y 刻度守卫断言;今日↔7 天同窗切换不闪断言(图表内容保持、同参重拉保留)。
- **AC5** 门禁与验收:`cd desktop/ui-src && npx vitest run` 全绿 + `tsc -b` 零错;像素级验收按主人判例 AI 亲验(截屏+度量到「不再是单点图、两端日期不同」),不留给主人当测试欠账。

## 4. 边界、约束与技术注记(design 阶段须解决)

- **数据耦合红线**:`buildOverviewStats` 的采集格是 trend **整窗求和**(`api.ts:535`),且概览四格与趋势卡同吃一份 trend(一窗一拉,补批四决议);趋势卡脚 `trendTotal` 同源。图窗放宽后,概览窗切片(今日=取当日行/末行)必须落在纯函数层并有测试——这是 R2 的实现面。
- 同理 `cumulativeOutcomeSummary`(累计成功率)现吃 outcome 整窗;已裁定跟图窗不切片(仅换标签,数字天然=拉数窗)——见 design D5,断言落 AC2/AC3。
- **协议零新面**:不改 store.trend / runs.trend 后端;不改 `OVERVIEW_WINDOW_DEFAULT`(今日仍是默认概览档)。
- 拉数形态(一窗拉宽 + 客户端切片 vs 今日档双拉)由 design 权衡,倾向前者(少一次往返,切片纯函数可测)。

## 5. 非目标

- 方向 B(今日档换形态:当日分轮柱状/大数字卡)。
- UTC/本地日期口径改写(「今日显示昨日日期」的次级困惑,如需另立)。
- 告警行截断样式、卡片高度/对齐等下半屏已排除项(实测无错位)。
