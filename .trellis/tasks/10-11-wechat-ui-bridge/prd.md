# 微信桥：UI 自动化 + 本地库只读（macOS 先行,Windows 备胎）

## Goal

微信信息获取与自动发送，双通道：**UI 自动化桥**（macOS AX 直驱先行，Windows wxauto 备胎；管「当下收发」）+ **本地库只读通道**（管「历史与全量」）。不破解协议，外部件走受管组件链路。

调研全记录见 [research/wechat-ui-landscape.md](research/wechat-ui-landscape.md)（2026-10-11 多路搜索 + 本机实测）。

## Requirements

### R1 读通道（信息获取）
- R1a UI 读：列出会话列表（名称 + 未读数）、读取指定会话最近 K 条文本消息（图片/文件类先落到「类型 + 占位描述」）——管「当下」。
- R1b 本地库只读（2026-10-11 主人追加）：对已登录账号落盘的 `db_storage/`（message/session/contact 域）做**纯本地只读查询**——深历史、全量检索，补 UI 只能看到已加载消息的短板。含：定位库 → 取密钥（途径按 D4 裁决）→ 解密**副本** → 只读查询。

### R2 写通道（自动发送）
- 向指定会话发送文本消息；首个联调对象固定为「文件传输助手」（安全测试对象）。
- 发送成功要有可验证回执（读回发送框/消息列表比对）。

### R3 双线结构
- **macOS 线（先行）**：AX 属性读 + AX 动作驱动本机微信客户端。
- **Windows 线（备胎）**：wxauto 系桥服务 + 局域网 HTTP，本档只落设计占位与启用判据，实现待 macOS 探查裁决后另启子任务。

### R4 账号无关
- 桥只操作「当前已登录账号」，不在桥内做账号管理/登录流程；小号 vs 主力号是主人侧运营决策（见开放决策 D1）。

## 约束（红线）

1. **不破解协议**：只驱动真实客户端界面层 + 只读本地落盘数据。禁协议逆向、禁 hook 注入。密钥获取**优先零内存方案**（key_info.db / 文件内材料 / 派生路径）；**内存密钥搜索为降级候选，启用前须主人裁决**（D4）——它是 PyWxDump/chatlog 路数，账号侧虽零风险但踩「不破解」精神边界。
2. **链接者架构**：外部开源件（wxauto-mac / wxauto 系 / sqlcipher 绑定）= 受管组件，走设置下载 + 配置，永不修改上游源码。
3. **禁 Docker**（主人铁律，agent-wechat 类容器方案已因此排除）。
4. **静默后台铁律**：桥不得抢前台焦点、不得合成鼠标点击、不得激活微信窗口；UI 侧只走 AX 通道（AX 属性读 + AXPress/AXConfirm 类动作）。本地库只读天然零前台扰动。验证取证按 MYIA_SMOKE_GEOMETRY / 后台窗口取证惯例。
5. **ToS 风险如实披露**：UI 自动化违反微信许可协议字面，封禁风险由腾讯裁量，本档不承诺零风险；UI 上不得隐藏此性质。**本地库只读不触碰网络与账号进程，账号侧零风险**（删库潮是腾讯对工具**分发方**的合规维权，自研自用读自己数据是另一性质，但此定性仅为本档工作假设）。
6. **私有数据红线**（security-baseline）：聊天记录内容属私有情报——解密副本只落 MYIA 私有数据区（数据根），不入 git、不入日志、不外发；外发先脱敏；探查命中只报位置与形状。
7. **版本脆弱性显式化**：微信升级可能破坏 AX 树 / 库 schema / 密钥方案，桥必须带版本探测 + 优雅降级（degraded 状态如实上报，不静默装死）。

## Acceptance Criteria

- [ ] **AC1 AX 探查报告**：微信 4.1.15 开窗状态下 AX 树能力清单实测（能读到会话列表？消息文本？发送框？Chromium 渲染层是否需要 AXManualAccessibility 激活？），附原始证据；含 wxauto-mac 对 4.1.15 兼容性实测结论（可用 / 部分 / 不可用）。
- [ ] **AC2 读**：桥能列出前 N 个会话（名称 + 未读数）并读出指定会话最近 K 条文本消息。
- [ ] **AC3 写**：桥能向「文件传输助手」发送一条文本并验证成功回执。
- [ ] **AC4 静默验证**：AC2/AC3 全程前台 app 与焦点不变（取证：前后前台进程对照 + 窗口列表对照）。
- [ ] **AC5 落地形态**：桥以受管组件形态接入 MYIA（组件戳 + 配置面），推送通道注册进 push 层，消息屏状态如实三态（可用/降级/不可用）。
- [ ] **AC6 备胎占位**：Windows 线设计占位段落档（栈选型 + 启用判据 + 与 macOS 桥的协议对齐），不实现。
- [ ] **AC7 本地库只读全链**：对已登录账号完成「定位 db_storage → 密钥获取（途径按 D4）→ 解密副本落 MYIA 私有数据区 → 只读查询指定会话最近 N 天文本消息」全链验证；全程零出网、零微信进程交互；副本与查询结果不进 git/日志，证据只留形状（库数、表数、行数、样例脱敏一条）。

## 开放决策（主人侧）

- **D1 账号**：专用小号（爆炸半径隔离，代价：实名注册 + 新号风控更敏感） vs 主力号（省注册，风险直接落主力号）。桥实现账号无关，此决策不阻塞开发，只影响联调时挂哪个账号。
- **D2 wxauto-mac 兼容性失败时的路径**：自研 AX 层 vs 借力 wechat-controller 思路（AC1 探查后裁决）。
- **D3 Windows 备胎是否真启**：看 macOS 线探查与稳定性结果（AC6 判据）。
- **D4 本地库密钥途径**（2026-10-11 新增）：零内存方案（key_info.db 材料 / 文件内密钥 / 派生）可用 → 直接用；不可用 → 内存密钥搜索是否豁免启用，主人裁决（涉及红线 1 边界）。

## Notes

- 本机已知事实（2026-10-11 实测）：微信 4.1.15 运行中但**主窗口未开**（托盘态，CGWindowList 全量 0 窗口）；会话宿主已有辅助功能权限（Dock/Finder AX 读取正常）；微信进程族含 WeChatAppEx + 5×Chromium Renderer helper → 聊天界面疑似 Web 渲染，AX 深探必须开窗后做（开窗涉及前台性，归执行段在主人知情下进行）。
- 本地库事实（2026-10-11 实测）：数据根 `~/Library/Containers/com.tencent.xinWeChat/Data/Documents/xwechat_files/`；当前账号目录 `wxid_oc2yhey1xkpw22_8253/db_storage/` 十四域分库（message/session/contact/sns/favorite/general…），message 域为分片库 + `-wal/-shm/-incremental.material` 增量件；`all_users/login/<wxid>/key_info.db`（活跃写入）为 D4 零内存密钥方案的头号探查对象；钥匙串无微信密钥条目（dump-keychain 元数据级核过，凭据红线内未深挖）。
- 官方零风险通道（企微 W2 / apprise 五通道）与本桥互补不互斥，见 research 文档 §4。
