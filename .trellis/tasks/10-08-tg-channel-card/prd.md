# PRD:TG 渠道卡 —— 情报流内按渠道聚合,点击进渠道详情

来源:主人 2026-10-08 晚令(附装机截图:`全部条目 · 滚动流`里 mihomo_party_group 一个频道连发多条,每条消息都铺成全量大卡,刷屏)。

## 需求

情报流消息流界面里,TG 渠道的内容以**渠道卡**呈现,不再逐条消息铺卡:

1. **渠道卡区置于消息列表顶部**(主人拍板:「情报流这个界面上面都放置这种卡片渠道」):每个 TG 渠道一张卡——频道名、最新一条预览、条数/未读计数、最新时间。
2. **点击渠道卡进详情**:进入该渠道的消息流(逐条消息气泡、可展开全文、标已读/星标/稍后读),即现有 source 作用域 L3 流,零新后端。
3. 消息列表本体不再出现 TG 消息卡(否则聚合无意义);其他渠道类型(新闻 RSS/优惠/监控/日报)维持现状逐条卡(主人拍板:只 TG)。
4. 过滤/搜索/当日窗/实时滚动全兼容:渠道卡的计数与预览从当前视图可见条目派生(未读页签下只计未读;采集事件到达即刷新)。

## 验收标准

- [ ] AC1 `全部条目 · 滚动流`与品类流:窗口内含 TG 条目时,列表区顶部出现「TG 频道」卡区,每渠道一卡(频道名=去 telegram- 前缀本名;最新一条预览单行截断;今日 N 条 · 未读 M;最新相对时间);TG 消息卡从下方消息列表消失,其他类型卡不受影响。
- [ ] AC2 点击渠道卡 → source 作用域消息流(面包屑可层层返回;从「全部条目」进的,面包屑含「全部条目」中间层可一键回流);渠道详情内消息逐条气泡、可展开全文、可标已读。
- [ ] AC3 计数诚实:渠道卡计数 = 当前过滤视图 ∪ 当日窗可见条目(title 注记口径);全部已读后未读数归 0;未读 >0 渠道卡带未读 accent 竖条。
- [ ] AC4 全 TG 流(如截图场景)不再误现「没有未读条目」空态;渠道卡区正常呈现。
- [ ] AC5 j/k 键盘巡游只在真实渲染的消息卡间移动(不落到已聚合离场的 TG 卡);空态判定含渠道卡区(有卡不空态)。
- [ ] AC6 门禁:vitest 定向(feed 屏)+ tsc + vite build 全绿;既有 TG 相关测试断言随新呈现更新,语义不丢(渠道详情气泡呈现仍有测试覆盖)。

## 边界

- 不动后端(store.items 的 category/source 独立可选已支持,entry.py:1680-1689 已核)。
- 不动 L1/L2 层级(品类行/渠道行照旧);渠道详情(source 作用域 L3)呈现零变化。
- 非 telegram 渠道类型五档呈现零变化。
