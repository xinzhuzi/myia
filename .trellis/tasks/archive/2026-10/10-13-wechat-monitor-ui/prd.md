# 微信监控 UI:取钥-解密-情报流全链界面

## Goal

微信监控的 UI 全链设计:把「取钥(LLDB 挂载)→ 自动解密 → 情报流自动监控」从「终端跑脚本+静默后台」升级为**应用内可视化编排**。数据源侧(群源声明/管线)由另一会话负责,本任务只做 UI 与壳层编排。

## 现状与缺口(2026-10-13 实锚)

| 面 | 已有 | 缺口 |
|---|---|---|
| 设置·微信卡(WeixinAccountCard) | 桥三态灯+登录指引+**取钥器路径配置**(B5) | **密钥状态行+「获取密钥」交互流**(现取钥=终端跑 lldb-shot.sh,应用内零入口) |
| feed·微信品类卡 | 品类图标/渠道卡/桥探针三态词面(2级桥状态区+3级监控台骨架) | 密钥缺失态的**行动引导**(现在只有 fix_hint 文案);监控台**内容化**(群列表+状态+最新消息) |
| 桥/引擎 | 密钥就绪后全自动(E2 副本/E3 查询/cron 拉取) | 取钥编排的**进度事件流**(provider progress 行已定义协议,UI 未消费) |

## Requirements

### R1 密钥状态面(设置·微信卡扩展)

- R1.1 密钥状态行,三态(grill 决议①:桥侧 `key-status` 命令即三态真源,**抽样重验**,不用 probe 的零成本判据——它只看文件在场,钥匙失配时会说谎):**已就绪**(库数+取得时间)/已失效(文件在场但抽样验真不过=微信版本变化后失配)/未获取(文件缺位)。取得时间=keys.json 文件修改时间(零格式变更;cache 不加元数据键以免破坏「键=库相对路径」消费方)。
- R1.2 「获取密钥」按钮→交互流(见 R2);ready 态按钮变「重新获取」且带二次确认(grill 决议②:key-acquire 缓存在场会短路,**必须 --force 才真取**——否则失效场景永远空转)。
- R1.3 取钥器路径配置行已在(B5),获取密钥按钮在未配置取钥器时如实置灰+引导先配置。

### R2 获取密钥交互流(核心新增)

- R2.1 三步式:**确认页**(预告:将弹出系统密码框+需要在微信里退出登录再扫码一次,全程只读瞬时断点)→**进行页**(实时进度:密码→连接微信→等待重新登录→派生验真;消费 provider progress 事件)→**结果页**(成功:N 库全验真+解密就绪;失败:人话原因+重试入口)。
- R2.2 密码经系统管理员对话框(osascript 提权件自理),应用全程**不读不存密码**。
- R2.3 进行页等待窗口 10 分钟(grill 决议⑥统一:请求 timeout_hint=600s,桥内帽 max(hint,120) 且上限 1800s,壳侧兜底帽 900s——三处数值以此为准)。
- R2.4 可取消(grill 决议③:用户态链直接杀;**提权段以 root 跑,用户态杀不动**——取消=写哨兵文件,部署件轮询哨兵即自杀+自清(内建 pkill 孤儿清理),最迟 10 分钟自灭)。
- R2.5 **文案判例(硬)**:LLDB/断点/寄存器/passphrase/挂载 等词**永不上屏**(「挂载」也是行话→「正在连接微信」);可见词面=「获取密钥」「从微信读取(需要重新登录一次)」「正在验证 N 个数据库」。

### R3 解密与监控状态(feed·微信三级监控台内容化)

- R3.1 三级监控台右栏=**监控群列表**(数据源=weixin 品类已声明源):每群一行=显示名+状态(监控中/密钥缺失/静默窗口)+最近一条消息预览+相对时间。
- R3.2 密钥缺失态:群行降灰+「去获取密钥」入口(跳设置卡 R2 流)。
- R3.3 群消息流=左栏既有时间线形态复用(与 TG 三级同族版式,微信绿色系)。
- R3.4 「AI中转站-♾️ AI Token」群由数据侧会话加源后自动出现在列表(源驱动,UI 零硬编码群名)。

### R4 监控群管理(三级监控台;grill 决议④降范围)

- R4.1 **一期只读**:群列表+状态+最新消息(零写面)。添加/暂停/移除**不建表单直写 yaml**——与数据源侧会话的双写冲突面一刀切断;入口=「去配置监控群」跳**既有 YAML 编辑屏**(仓库已有 yaml-editor,weixin.yaml 可视化编辑),编辑后下轮 cron 生效。
- R4.2 二期(数据侧源管理契约稳定后翻案):sessions 选择器/一键添加表单挂数据侧契约。

## Acceptance Criteria

- [ ] AC1 设置卡:密钥三态行+按钮态联动(未配取钥器=置灰引导;已就绪=库数/时间+「重新获取」带确认;失效/未获取=「获取密钥」直发)。
- [ ] AC2 获取密钥流三步齐;进行页进度事件实时刷新;取消后用户态进程零残留(ps 核验)+哨兵文件落地(提权段最迟 10 分钟自清,验证哨兵机制本身)。
- [ ] AC3 密码全程不出现在应用进程内存日志/网络面(osascript 独立提权件)。
- [ ] AC4 文案审计:全 UI 面 grep 不到 LLDB/断点/passphrase/挂载 字样。
- [ ] AC5 群列表渲染**机制**用合成源夹具验证(vitest+装机器械验证);**真实两源在列(TMS+AI中转站)=数据侧里程碑后的补验项,显式依赖挂账**(grill 决议⑧:本任务不等数据侧)。
- [ ] AC6 「去配置监控群」跳 YAML 编辑屏链路通(一期只读版 R4);编辑生效留给既有 YAML 面的验收域。
- [ ] AC7 门禁全绿(vitest/tsc/cargo+pytest)+装机包刷新+像素级验证(三屏:设置卡/获取流/监控台)。

## Constraints

- 红线:零微信进程干预的红线中,取钥器外部件的瞬时断点已是主人批准的唯一例外(UI 只编排,不新增干预形态);密钥内容永不上屏不上日志。
- 分工:数据源侧(源声明/管线/超时协议桥侧实现)归另一会话;**桥侧与 Rust 壳侧改动前先探活避让**(并行会话在途,见 design §6)。
- 版式:全部挂既有版面(设置微信卡/feed 三级结构),不新造画布(独占画布判例)。
